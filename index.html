Um portal que reúne os painéis da empresa em uma única página de cartões. Cada cartão leva a um painel, e a lista é mantida por uma área administrativa: cadastrar, editar ou remover um painel não exige mexer no código.

00 · O desafio

Muitos painéis, nenhum lugar para encontrá-los.

Cada painel nasce como um projeto separado, com o seu próprio endereço. Com o tempo, os links ficam espalhados entre mensagens, favoritos e e-mails, e quem precisa de um número não sabe por onde começar. A Central de Painéis resolve isso com uma página só, onde cada painel aparece como um cartão.

Onde fica o painel daquele cliente? Na central, com nome, descrição e um clique.

ENCONTRAR

Uma página para tudo

Todos os painéis lado a lado, cada um com nome, uma frase sobre o que mostra e o link de acesso.

MANTER

Sem tocar no código

Um painel novo entra pela área administrativa: nome, descrição e URL. A home se monta sozinha.

CONTROLAR

Quem pode alterar

A lista é pública para leitura; cadastrar, editar e remover painéis ou administradores é tarefa da área administrativa.

01 · Princípios

A home não sabe quais painéis existem.

Ela apenas lê uma lista e desenha um cartão para cada item. Essa separação guiou o resto do projeto:

01

Dados fora da tela

Os painéis vivem em uma lista (data/paineis.json), não no HTML. Acrescentar um painel é acrescentar um item.

02

Campos mínimos, o resto deduzido

Sem inicial, a home usa a primeira letra do nome. Nome e URL são exigidos no cadastro, então todo cartão leva a um painel real.

03

A página nunca fica vazia

Se o arquivo de dados não carregar, a home usa uma lista de reserva escrita no próprio código.

04

Nada real na demonstração

Sem login, sem e-mail e sem banco. As edições ficam só no navegador de quem testa, e os administradores são fictícios.

02 · Os dados

Cinco campos descrevem um painel.

O arquivo data/paineis.json é uma lista simples. Cada painel tem cinco campos; nome e URL são obrigatórios:

03 · A home

Um cartão por painel, montado na hora.

A home é uma página só, com um título, o link para a administração e uma grade que se ajusta à largura da tela (auto-fit, cartões de no mínimo 260 px). O JavaScript lê a lista e cria cada cartão:

Carrega a lista

navegador, JSON ou reserva, nessa ordem

Completa o que faltar

inicial a partir do nome, quando não houver

Desenha o cartão

ícone com a inicial, nome, descrição e “Acessar painel”

Decide como abrir

links externos (http ou https) abrem em nova aba, com noopener noreferrer; links internos abrem na mesma aba

Visual da central

Fundo azul-ardósia em gradiente, cartões translúcidos com desfoque e ícone em degradê de azul-céu para lilás. Ao passar o mouse, o cartão sobe e a borda acende.

Sem dependências

HTML, CSS e JavaScript puro, sem framework e sem etapa de build. O que está no repositório é exatamente o que o navegador recebe.

04 · Administração

Duas abas: painéis e administradores.

A área administrativa concentra a manutenção da central. Na demonstração, tudo o que é alterado fica salvo no localStorage em duas chaves: portfolio_paineis_publicados e portfolio_admins.

ABA PAINÉIS

Cadastro e edição no mesmo formulário

Nome, descrição e URL. “Editar” preenche o formulário e troca o botão para “Salvar alterações”; “Remover” pede confirmação. Nome e URL são obrigatórios.

ABA ADMINISTRADORES

Usuário, e-mail e data de criação

Criar um administrador e, para cada um, alterar o nome de usuário, o e-mail ou a senha, ou excluir. Cada ação abre uma janela com apenas os campos necessários.

Usuário principal

Marcado com o selo PAI. O botão de excluir fica desativado para ele.

Senha simulada

Na demonstração, trocar a senha só confirma a ação na tela; nenhuma senha é gravada.

Efeito imediato

Ao voltar para a home, os cartões já refletem o que foi cadastrado, editado ou removido.

06 · Deploy

Enviou para a main, está no ar.

A publicação no GitHub Pages é feita por um workflow do GitHub Actions (.github/workflows/pages.yml). Ele roda a cada envio para a branch main ou manualmente, e publica a pasta inteira do repositório:

Checkout

actions/checkout@v4 baixa o repositório

Configura o Pages

actions/configure-pages@v5

Empacota o site

actions/upload-pages-artifact@v3, com a raiz do repositório como conteúdo

Publica

actions/deploy-pages@v4 devolve o endereço da página no ambiente github-pages

Permissões mínimas

O workflow só lê o conteúdo e escreve no Pages (contents: read, pages: write, id-token: write).

Um deploy por vez

O grupo de concorrência pages evita duas publicações simultâneas, sem cancelar a que está em andamento.

Sem Jekyll, com 404

O arquivo .nojekyll publica os arquivos como estão, e o 404.html leva endereços antigos para o lugar certo.
